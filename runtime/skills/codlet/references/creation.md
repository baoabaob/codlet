# 创建或修改 Codlet 插件

先读 `runtime.json` 和 `plugin list --json`，确定当前实例、已有插件和 Core 能力。用户要求创建或修复时，直接完成可用版本；只有行为、目标或新增权限范围无法确定时才澄清。

1. 需求不清楚时，先澄清触发时机、预期行为、界面或输入输出，不擅自扩大功能
2. 沿用已有名称和 ID；未指定时按功能取易懂的名称和稳定的 `dev.<slug>` ID，检查与已安装插件是否冲突
3. 沿用用户指定的工作区；未指定时在 `runtime.json.defaultPluginProjectsDirectory/<slug>` 创建源码项目，先检查目录冲突。`defaultPluginsDirectory` 和 `packages/` 用于安装副本，不能作为源码项目位置；运行时技能目录也不能存源码
4. 需要与客户端一致的控件时使用 [官方 UI 参考](official-ui.md)，简单 DOM 功能不引入无关组件。沿用用户界面选择，不为了组件选择发起额外问卷
5. 功能大致敲定后，检查 `plugin list --json` 的 `coreProviders` 和所需能力。客户端集成优先使用 Core 的 `context.codex`，无需用户选择或另装官方 Adapter。确需其他业务插件时才说明新增依赖。只有标准 SDK 确实缺少相关能力时，说明具体未适配边界、兼容维护责任和必要特殊权限
6. 用一句话说明名称、位置、运行方式和必要权限，然后继续已授权的实现。只有新增读取文件、联网、执行程序或 Native 私有接口等范围超出用户请求时才询问，不能顺手请求全部权限

创建阶段先按当前运行实例的平台与客户端语言完成可用版本，不提前展开发布平台、i18n 和仓库问卷。用户已明确的跨平台、多语言或发布需求照常执行；缺失信息若会阻碍当前功能，仍及时澄清，不能为了延后发布问询而忽略当前使用要求。

读 [开发契约](plugin-api.md)，仅按实际层级加载类型和详细文档。需求是修复已有插件时保留已确定的选择。

- 使用 `codlet.json` 和构建好的 CommonJS 入口；TS 先构建，Core 不执行 npm 安装或即时编译
- 前端私有接口/节点依赖必须检查当前客户端源码和真实结构，不凭截图或模糊文字猜；验证普通消息和其他功能不受影响
- 标准 SDK 的平台和 Native 适配由 Core 负责，插件默认声明 SDK/能力要求。选定外部程序、Shell、Native 私有 DOM/主世界、原始 CDP 或完整 Node Host 等未统一适配功能，才需要作者声明相关兼容范围；保留实际测试证据，不能把声明或静态扫描当作实机通过
- 实现停用清理：移除自己的节点/样式，断开 observer、监听、定时器，取消请求，重载不重复注册
- 验证实际功能；有 UI 就验收浅/深色和合理窗口宽度，多语言还要检查切换、回退和文字溢出。未做的设备验收在开发记录中明确记录，不把假设写成已通过的测试
- 使用 [管理 CLI](management.md) 预览并按已授权范围安装。安装会复制整个插件目录，源码保留用于修改和分享；不要删除仍需维护的项目
- 修改源码后先构建，再用 `plugin add <source-directory> --update --trust [--grant <permission> ...] [--enable] --json` 更新副本，保留原启停状态和 broker 策略。`reload` 只重启安装副本，不同步源码；`--replace` 会清空数据，不用于普通迭代。同 ID 冲突先核对来源
- 用户已经要求安装并启用时直接完成。额外上传到 GitHub、发布或扩大权限需要对应授权
- 最后简述名称、目录、用法、验证和限制

## 分享与发布

本地创建与必要验证完成后交付用法和源码位置。仅请求自用时到此结束；用户要求分享或发布时，再准备安装包。包只包含 manifest、构建入口、必要资源、说明和许可证，排除凭据、用户数据、日志、依赖缓存和开发产物。

选择发布后，再合并询问尚未明确的信息：

- SDK/能力要求：普通插件沿用统一 SDK，不默认向作者发起操作系统问卷；涉及未适配功能时才确认该部分的平台/客户端限制和实测范围
- 语言范围：是否跟随客户端语言，支持哪些语言（可推荐中文和英文），还是保持单一语言。官方 UI 组件不自动提供插件文案的 i18n；多语言需覆盖名称、说明、菜单、设置、状态和错误文案，并有翻译回退。技术 ID、权限名和标签不翻译
- 发布目标与资料：仓库、可见性、版本、作者和说明，以及安装依赖、许可与必要的使用文档；先沿用已有信息，不逐项重复确认

随后补齐已确定范围的实现、测试、包元数据和安装包。准备可审阅的发布结果，按用户已授权的仓库和可见性执行；没有获得公开发布授权时，不把本地可用或同意私有上传解释成允许公开。支持声明与真实平台验收记录分开，不补写未执行的测试。
