# M2 Core RPC：执行器之间的通用能力调用

Host 和官方 renderer executor 使用同一组能力声明、Core 身份、代次和作用域规则。
支持 Host→Host、Host→renderer、renderer→Host、renderer→renderer，以及 Core 的
`codlet.runtime.ping@1`、`codlet.runtime.manage@1`。方法名和业务 JSON 由 provider 定义；
Core 不把 Codex 页面、thread 或 turn 私有对象放进通用协议。

## 声明与启动

描述符为 `{name, api, scope}`，三项必须与该 entry 的 `requires` 精确匹配。
Host 可提供 Runtime 或 Target 能力；每个 renderer 实例只提供 Target 能力，但可消费两种
作用域。Host-only 包的顶层 `provides`/`requires` 属于 Host；组合包的顶层声明属于 renderer，
`host.provides`/`host.requires` 属于 Host。API 不匹配、提供者冲突、缺失要求和依赖环会拒绝启动。

Core 对 entry 排序。组合包 renderer 另有一条依赖自身 Host Ready 的生命周期边，所以 Host
等待自身 renderer 是实际依赖环。跨窗口启动先登记所有文档，再让一个 renderer entry 在
全部目标就绪，然后启动其后续消费者；等待过程继续泵送 binding 和 Host RPC。
Host 初始化可以等待另一个无环 renderer provider。解析时就固定 provider generation，
等待 Ready 不会改为调用后来的另一代，也不会更新原始截止时间。

## Host SDK

```js
const math = { name: 'example.rpc.math', api: 1, scope: 'runtime' };
const value = await context.rpc.request(math, 'double', { value: 3 }, {
  timeoutMs: 1000,
  signal: abortController.signal
});
await context.rpc.notify(math, 'count');

context.rpc.provide(math, 'double', async (params, invocation) => {
  // caller、scope、generation 和 depth 来自 Core，业务 params 不会覆盖它们。
  return { value: params.value * 2, caller: invocation.caller };
});
```

`request(descriptor, method, params?, options?)` 返回 `Promise<T>`。
`notify` 的参数相同，返回 `Promise<void>`：Core 等到该 handler 结束后确认，丢弃其业务返回值，
错误仍使 Promise 拒绝。它不是持久消息队列。

`options` 包含 `timeoutMs`、`signal`，Host 另可传 `scope`。默认超时 15000 ms，范围为
1…15000 ms。回调的 `invocation` 提供冻结的 `caller`、`scope`、`capability`，以及 `depth`、
`signal`、`remainingMs()` 和 `rpc`。Host 用 AsyncLocalStorage 让异步延续中的受管理 RPC、
CDP 和 OS 调用继承同一个父调用预算与取消。

Host JSONL request 可携带顶层 `timeoutMs`（1…15000）；旧请求省略该字段时仍使用原默认值。
SDK 会把实际剩余预算写入该字段，Core 从收到帧的时刻固定截止时间，再与父调用和 cleanup
预算取最短值。OS 的短超时因此不依赖 Host JavaScript 及时处理计时器或发出取消通知。

## Runtime 与 Target

Runtime 是一次 Core 运行内的单例作用域，退出 Core 后结束。Host 的根 Runtime 调用无需
选择窗口。由某个 renderer 文档发起的 Runtime 调用仍绑定该调用者文档；文档退休后，
其待处理请求也会失效。

主动选择 Target 使用 Core 签发的句柄：

```js
const { sessionId } = await context.cdp.request('Target.attachToTarget', {
  targetId: selectedTarget.targetId,
  flatten: true
});
const scope = await context.rpc.target({ sessionId }, { timeoutMs: 1000 });
const result = await context.rpc.request(targetCapability, 'inspect', null, { scope });
await scope.close();
```

`rpc.target` 只接受该 Host 当前代经 Core raw attach 成功取得并记录归属的 flattened session。
Core 启用 Page 生命周期、读取当前 frame 后返回冻结的 `{kind:'target', close()}` 对象；对象
内部凭证不能序列化为另一个 Host 的授权。payload 自报 `targetId`/epoch、另一个代次或另一个
Host 的句柄均不能建立作用域。此路径不需要官方 renderer ABI；纯 Host→Host Target 调用也
使用它。Host→renderer 还要求同一 Target 当前文档的真实 provider realm 已 Ready。

Target handler 默认继承其入站作用域，通常不必另传 `scope`。显式句柄可以选择另一个已获准
Target，同时仍保留父调用的截止时间和取消链。`close()` 取消使用该句柄的未完成请求，
不关闭其它消费者的 Target，也不等于 raw detach。

导航、Target 销毁、所属 raw session 结束、授权撤销或 owner 代次退休都会使旧句柄失效。
仍存活的同一 owned session 可再次经过 `rpc.target` 验证，取得新句柄；旧凭证不会升级。
`scope.epoch` 是 Core 的不透明生命周期值，不应当作页面导航计数。
Backend-session/thread 等作用域需要后续 adapter 的显式生命周期，M2 不接受任意字符串代替它们。

## Renderer SDK 与取消

renderer 的 `rpc.request` 增加第四参数 `{timeoutMs?, signal?}`。单个 requirement 的历史
`request(method, params?, options?)` 简写保留。renderer `notify` 保留既有同步、无响应 id 的
ABI：Core 有界执行，失败记入诊断，调用者没有交付 receipt。

浏览器没有 Host AsyncLocalStorage。provider 的异步嵌套调用必须使用 `invocation.rpc`：

```js
context.rpc.provide(viewCapability, 'calculate', async (params, invocation) => {
  return invocation.rpc.request(mathCapability, 'double', params);
});
```

这个绑定客户端携带 Core parent token；普通 `context.rpc` 是新的根调用。Core 检查 token
对应的 plugin、generation、Target/session、document epoch 和 execution context。伪造或跨
realm 的 token 会被拒绝。用户信号、祖先结束、超时或作用域退休都会结束受管理子调用；
晚到结果不会传给新代次。取消不逆转已经完成的 CDP 或 OS 外部效果。

## 授权与归还

每份实际加载的本地 entry 都保留源快照当时的完整 `path + grants + brokerPolicy`。
Host/renderer 的受管理 admission、provider dispatch 和结果交付对照当前完整记录；candidate
和 rollback 用自身快照，不能从尚未提交的旧 catalog 借用权限。空闲 Host pump 只检查进程内
原子状态。`enabled` 是独立的生命周期偏好：合法 enable 候选和有限 cleanup 不靠临时改授信运行。

Core 记录的 raw session 也属于可归还资源。普通 stop 先让仍获准的旧插件完成其原有限
deactivate 清理，再由 Core 直接 detach 遗留 session。撤掉 `cdp.raw` 后不会把权限重新暴露给
旧插件，Core 仍可直接归还自己记录的资源。OS receipt 取消后继续被持有，直到 worker/Job
真正归还；无法确认则返回 `cleanup_incomplete`，不允许成功 replacement receipt。
详见 [OS broker](OS_BROKER_2026-09-10.md) 和 [组合包生命周期](COMBINED_PACKAGES_2026-09-10.md)。

raw attach 的调用者取消、超时或退出时，已经开始写出的请求仍由 Core 独立持有其确切响应
receipt；晚到的成功 sessionId 直接进入 Core detach，不再交给插件。尚未开始写出的 frame
可取消并证明没有创建远端资源。独立退休观察最多 1500 ms，计入原停止预算；如果已写出的
attach 始终不返回，就无法识别要归还的 session。此时 Core 报告 `cleanup_incomplete`、隔离
旧代并终止共享 CDP 连接，使该连接的远端 session 命名空间结束。这个确定失败会影响本次
Codlet 会话；不能声称只影响该插件。普通 Host 方法超时/崩溃仍保持既有隔离行为。

已知 session 的归还也有持久于 caller 的有限队列：每个 Host 同时最多派发四个 detach，
共享 raw writer 满时保留队列并在同一个绝对截止时间内重试。只有确认 detach 或共享连接
结束才释放对应的 128-session 配额。预算结束且已知资源仍未归还同样报告明确失败并关闭
连接，不因队列满而丢掉 cleanup 项。

## 有界资源与错误

| 资源 | 上限 |
| --- | --- |
| 单次原始请求预算 / 嵌套调用深度 | 15 秒 / 8 跳 |
| 一个 Host 的 outbound RPC / raw CDP / OS 请求 | 各 4 个 |
| Host provider 活跃调用 / endpoint | 4 / 256 |
| Host capability 全局未完成或未消费结果 | 16，入队 8 |
| 一个 renderer 的 pending SDK 请求 / provider 调用 / endpoint | 16 / 4 / 256 |
| Core renderer request / renderer invocation token | 64 / 32 |
| Target scope / opaque handle / owned raw attach（含预留） | 64 / 64 / 128 |
| Core entry identity 历史 | 8192，退休代次不复用 |

通用 JSON payload 约 1 MiB，并为协议 envelope 预留空间；OS broker 使用更小的独立限额。
Core 的生命周期观察器只接收必要事件，队列 128、单事件 8 KiB。溢出会保守退休 scope/lease，
保留 raw 会话归属供重新验证和最终归还。公开 raw 订阅仍采用原来的四事件边界。
公开 `cdp.subscribe` filter 可增加 `methods`（1…32 个不同的精确事件名）；Core 在复制事件
和占用队列额度前筛选，未指定时保持原来的全部匹配行为。

常见错误包括 `capability_denied`、`scope_required`、`scope_denied`、`scope_ended`、
`authorization_revoked`、`rpc_depth_limit`、`invocation_cancelled`、`request_timeout`、
`request_limit`、`host_unavailable`、`provider_unavailable` 和 `method_not_found`。
renderer 本地计时器保留旧 `rpc_timeout` 错误；远端 Core 超时为 `request_timeout`。
