# M2：独立 OS broker 与持久授权

Core 提供相互独立的 `host.fs`、`host.network`、`host.process`、`host.system` endpoint。
原有 `cdp.raw` 保留自己的接口和授权。每个 endpoint 都要求当前 Host manifest 已声明对应
permission，而且该目录的完整 registry 记录明确授予了它；额外 grants 不会变成声明。

这些约束作用于 Core 管理的调用。Host Node 和获准运行的子程序仍以当前 Windows 用户
身份执行，不是 OS 沙箱；撤权也不能逆转代码已造成的外部效果。

## 首次授信与完整记录

注册前可运行 `plugin add <directory>` 只读查看目录和声明。保存需要 `--trust`、每项
`--grant` 以及该 broker 需要的明确范围；CLI 在保存前显示声明、grants 和规范化后的 policy。

```powershell
codlet plugin add C:\Plugins\my-tools --trust --grant host.process --grant host.fs --grant host.network --grant host.system --read-root C:\Fixture\approved-data --network-origin https://example.com
codlet plugin permissions dev.my-tools --json
```

registry schema 2 的 `localPlugins.<id>` 记录为：

```json
{
  "path": "C:\\Plugins\\my-tools",
  "grants": ["host.process", "host.fs", "host.network", "host.system"],
  "brokerPolicy": {
    "readRoots": ["C:\\Fixture\\approved-data"],
    "networkOrigins": ["https://example.com"],
    "executables": []
  }
}
```

实际路径由 CLI 规范化为已选择的本地 canonical 路径。每种范围最多 32 项；没有默认的
文件目录、网络 origin 或子程序。`--read-root`、`--network-origin`、`--executable` 可重复。
`readRoots` 需要 `host.fs`，`networkOrigins` 需要 `host.network`，`executables` 需要
`host.process`。Origin 只包含 HTTP(S) scheme、host 和可选 port，拒绝通配符、凭据、路径、
query 和 fragment。子程序范围只接收已存在的 `.exe` 文件。

`path + grants + brokerPolicy` 是一个原子比较的完整授信记录。并发编辑任何部分都会使
基于旧记录的 save 冲突，不会覆盖另一方的范围变更。旧 schema 2 记录省略 `brokerPolicy`
时按空策略读取；空策略仍省略输出，旧注册格式没有增加强制字段。

`host.process` 继续是启动托管 Node Host 的必要 grant；它不会自动开放 `process.run`，
后者还必须命中显式 `executables`。允许通用解释器或 shell 可执行程序意味着允许使用该
程序的功能，Core 不会根据参数内容把它变成沙箱。

## SDK 和 endpoint

Host SDK 使用以下方法，参数均为对象；可选 `options` 包含 `timeoutMs` 和 `signal`。
`system.info(options?)` 没有业务参数。它们通过原有版本化 Core RPC 传输，返回 DTO 不作
隐藏转换；无需自行构造 JSONL。

| SDK | Core endpoint | 参数 | 结果 |
| --- | --- | --- | --- |
| `context.fs.readText(params, options?)` | `host.fs.readText` | `path`, `maxBytes?` | `text`, `bytes` |
| `context.fs.readDir(params, options?)` | `host.fs.readDir` | `path`, `maxEntries?` | `entries: [{name, kind}]`, `truncated` |
| `context.fs.stat(params, options?)` | `host.fs.stat` | `path` | `kind`, `bytes`, `modifiedUnixMs` 或 null |
| `context.network.fetch(params, options?)` | `host.network.fetch` | `url`, `method?`, `headers?`, `maxBytes?` | `status`, `url`, `headers`, `body`, `bytes` |
| `context.process.run(params, options?)` | `host.process.run` | `executable`, `args`, `maxOutputBytes?` | `processId`, `exitCode`, `stdout`, `stderr`, 字节计数和 `jobReaped` |
| `context.system.info(options?)` | `host.system.info` | 无 | `os`, `architecture`, `logicalCpus` |

文件路径必须是本地绝对路径。目录与 executable 授权只统一本地 drive 字母的大小写及
普通/verbatim 路径表示，其余路径组件按 UTF-16 精确匹配；即使当前卷不区分大小写，
`foo` 的授权也不接受 `Foo`，避免在 NTFS 大小写敏感目录中扩大范围。Core 在任何路径
查找前先做纯词法授信范围检查，再从本地 drive 根逐段以 `OPEN_REPARSE_POINT` 打开并
持有句柄；祖先禁止删除共享。任一 junction、
symlink、hard link、设备名、ADS、dot segment 或真实句柄路径不匹配都会拒绝。这样在
`readRoots` 下指向 UNC 的链接也不会先触发目标解析或网络 I/O。读取只支持普通 UTF-8 文件；
没有写入、删除或递归遍历 endpoint。目录列表默认 128 项、最多 256 项，结果注明截断。

网络 fetch 支持 GET 和 HEAD，严格匹配已授 origin。它不跟随任何重定向；3xx 作为普通响应
返回，因此跨 origin 请求必须再次明确经过 policy 检查。没有环境/系统代理继承，也不接受
Host、proxy 或 hop-by-hop header 覆盖。请求 headers 最多 32 项/16 KiB，返回 headers
最多 64 项/16 KiB。Body 为 UTF-8 文本，按接收 chunk 计数，不依赖可信 Content-Length。
HTTPS 保留 TLS 证书校验。传输使用 [Reqwest 的超时、重定向和代理控制](https://docs.rs/reqwest/0.12.28/reqwest/struct.ClientBuilder.html)。

子程序只能按明确的 executable 和字符串 `args` 数组启动；没有 shell command 字符串、
交互 stdin、任意 cwd 或调用者环境变量注入。cwd 固定为原插件目录；只传递最小 Windows
环境。最多 64 个参数，每个 8192 字节，总计 64 KiB。Core 在恢复主线程之前将子程序放入
自己的非继承 Job；主程序退出时也会清理剩余后代。输出必须为 UTF-8。

文件、HTTP body 与合计进程输出默认限额为 64 KiB，显式上限为 256 KiB；请求和结果的
完整 JSON 也限为 256 KiB，编码膨胀后超限同样拒绝。system 只返回上表三个受限字段，
不枚举用户文件、环境变量、账户、主机名或进程列表。

## 预算、取消与回收

一个 broker 固定四个 OS worker，排队请求最多八个，未完成或尚未取走的结果合计最多
十六个。取走/丢弃 receipt 和 worker 都结束后才释放保留额度，不会用隐藏取消任务绕过
上限。每个请求使用原始绝对 deadline，最长 15 秒；Host 初始化或嵌套 RPC 的更短父预算
继续向下约束它。没有每次 OS 调用临时增加的 I/O worker。

网络使用 Hickory 的异步 DNS resolver，在对应 worker 的 current-thread Tokio reactor 上
运行，避免取消系统 blocking DNS 后留下不可等待的查询线程。HTTP 请求取消会结束其
future；可复用 resolver/连接基础设施由整个 broker 持有。broker stop 停止接收、取消当前
请求、明确结束尚未执行的队列项，随后丢弃 HTTP/resolver client、关闭 reactor，并等待
四个 worker 真正退出。HTTP receipt 的取消不代表整个 broker 的基础设施已经停止。

取消或撤权立即阻止新的受管理调用，但 receipt 的 terminal result 不冒充资源已回收。
process 路径会先终止 Job，再等到确切主进程退出、Job 为空、pipe 已归还后交付取消/超时
结果；最多另有两秒清理预算。无法确认时返回 `cleanup_incomplete`。broker stop 的 worker
确认预算为三秒，未确认则返回 `broker_stop_timeout`，不会报告“零残留 worker”。

空闲 owner pump 和尚未完成的 OS receipt 只检查进程内原子 token；实际 admission、OS
执行和结果交付核对最新完整 registry 记录。前台的周期 reconcile 共享一次 registry 读取，
显式 revoke 直接失效 token，不依赖 mtime 缓存。

## 撤权与代次

```powershell
codlet plugin revoke dev.my-tools host.fs --json
codlet plugin operation '<receipt>' --json
```

撤权保存完整记录：移除选中的 grant，同时清空对应 broker 范围。在线前台立即失效该
generation 的授权、停止它及传递依赖者；不自动恢复已撤权的旧快照。离线修改需先证明
对应 registry 没有运行中的 Host。之后的新授权需要明确保存的 grants/policy 和新 generation，
同一 broker 内旧 generation 永不复用。

Core 使用不可序列化的 `OsAuthorization`；插件不能通过 params 伪造它、转给另一个 broker
或修改 owner ID/generation。已完成但尚未交付的结果也要再次核对当前记录。记录移除、
path/grants/policy 变化或无法读取时，旧授权不能继续使用。`enabled=false` 本身不替代这项
授信检查，因为 enable 候选在最终提交 enabled 前就需要合法使用明确已授的 endpoint；
启停由前台 receipt 控制。

有限 cleanup 与普通授权分开：普通 token 撤销后，只要原 manifest/record 和当前原目录
仍授予 `cdp.raw`，Node 的旧代 cleanup 仍可在原清理预算内归还 raw 资源。撤掉 `cdp.raw`
本身、取消注册或改变目录则拒绝。这个判断不能复活普通 OS 调用。

## 隔离验收

[host-os-broker 示例](../examples/host-os-broker/README.md) 在真实托管 Node 中使用这些公开
SDK 接口读取显式目录、访问本地 HTTP fixture，并查询系统信息。验收随后撤掉 `host.fs`，
确认旧 generation 的再次调用被拒绝。

`tests/os_broker.rs` 覆盖实际示例、声明与 grant 交集、完整记录/结果撤权、代次与跨 broker
身份、文件范围及 dangling junction 的解析前拒绝、HTTP origin/redirect/headers/字节数/
deadline/cancel、参数数组、合计输出限制、带后代的真实进程 Job 回收及保留结果上限。
`tests/plugin_permissions.rs` 覆盖 policy 规范化、schema 2 兼容、完整记录并发冲突和单项
scope 撤销。这些检查只使用独立临时目录、loopback HTTP 和测试自行启动的 Node 进程树。
