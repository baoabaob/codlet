# 流量接管基础能力：Core 与 Desktop Adapter

状态：基础实现与 Windows 验收完成，2026-09-20。用户要求提供插件可组合的基础能力；API 选择、重试、容错、协议转换和界面由具体插件实现。本项不参考或移植某个网关产品，不制作发行包，不增加 Linux 适配。公开契约见[插件流量通道](TRAFFIC_CHANNELS.md)。

## 目标与验收边界

普通插件应能接入一条明确指定的请求通道，读取真实请求，修改目的地址、方法、头或正文，读取并修改真实响应，也可以显式拒绝或直接响应。接口须交代它接管的是哪条通道，不能把修改提交文本、页面事件或 AppServer RPC 等同于接管实际模型 HTTP 请求。

现有 `host.network.fetch` 是插件自行发出的 GET/HEAD 请求，`cdp.raw` 是 Chromium 调试通道，`codex.ui.preSubmit` 是提交文本和附加上下文的钩子。三者继续兼容，但都不被重新解释为全客户端流量接口。

本次交付覆盖通用的、显式接入的 HTTP(S)、HTTP 流/SSE 和 WS/WSS 通道：Core 提供受插件代次管理的本机端点与双向处理接口；调用方把该通道作为自己的服务地址后，真实请求才流经它。官方 Adapter 使用统一通道描述屏蔽客户端配置和底层协议差异，按通道实际能力设置客户端传输。插件可自行实现路由，Core 不选择供应商、模型或恢复策略。

| 通道 | 本次契约 |
| --- | --- |
| 经过显式接入端点的 HTTP 请求 | 可以观察、转发、修改或直接响应；包含正文 |
| 上述通道的 HTTP 响应及 SSE 字节流 | 可以逐块读取/变换；支持取消和背压，不要求整包缓存 |
| Codex AppServer 的模型请求 | Adapter 通过受支持的新建/恢复线程配置接入自定义服务地址；只有真正经过该地址的请求在范围内 |
| 已运行且没有接入端点的线程、官方 OAuth 内部请求 | 不声称自动覆盖；不得通过修改用户全局配置或安装根证书隐式接管 |
| Chromium 的任意网络请求 | 现有 `cdp.raw` 继续可用；受管 Fetch 拦截与网关是不同的 transport，不能混淆覆盖范围 |
| WebSocket / WSS | 纳入本次：握手、双向文本/二进制消息、修改/丢弃、关闭、取消、背压与限额；不自动重连或重放 |
| CONNECT / TLS 中间人 | 不做全局加密流量劫持；客户端显式连本机通道，由通道向 HTTPS/WSS 上游建立正常 TLS 连接 |

## 分层

### Core：通用生命周期与传输

- 新能力使用显式权限和当前 generation 授权；撤权、禁用、重载、Host 异常退出及 Core 关闭都会释放监听器、连接和进行中的处理。
- 通道仅监听 loopback，使用不可猜测的通道入口或凭据，限制并发、头部、正文及队列大小；返回可查询的范围与状态，不记录正文和认证信息。
- 请求/响应结构使用 HTTP 通用字段、二进制字节流和 `AbortSignal`，不出现 thread、turn、provider、model 或 Responses 专属字段。
- 插件显式决定下一步：转发原请求、改后转发、直接响应或拒绝。转发不是自动重试；一个请求不会因为 callback 超时被悄悄重复发送。
- 提供流式读取与转发；慢消费者以背压限制内存。正文变换后重新处理长度/传输编码头；剔除逐跳头，不把入站通道凭据泄漏给上游。
- WebSocket 两个方向分别串行处理，保留消息边界、文本/二进制类型与关闭语义；限制消息和待处理队列，不把一条无限流缓存成大包。子协议与握手失败应明确处理。
- 上游地址逐次校验获准 origin，重定向不得绕过边界。切换到不同 origin 时认证头不得被默认继承，需插件明确指定。
- 决策超时、处理器抛错和中途断流返回明确失败。已经发送响应字节后不拼接另一份响应、不自动从头重放，不伪造业务成功。
- Host JS 是有进程权限的原生代码，不宣称这些 API 限制是 OS 沙箱。受管接口仍须执行其授权及清理契约。

### 官方 Desktop Adapter：客户端接入

- 复用当前 Desktop 的原生连接，通过版本 profile 与公开协议形状核验接入点，不另起生产 AppServer。
- 提供选择通道、查询支持范围和撤销接入的接口；插件返回统一的 `{endpoint, protocols}` 描述，Adapter 按真实能力配置 HTTP/WS，无需插件知道客户端的 `supports_websockets` 等字段。以新建/恢复线程时的临时配置传递服务地址，不落盘修改用户的全局 `config.toml`、登录文件或系统代理。
- 在需要时暴露用于挂接现有请求通路的 callback API；沿用 capability 声明、一次性 ticket、调用者 generation 与注销规则。
- 接入仅承诺明确报告的协议/线程生效时机。当前正在进行的请求不因修改配置而自动迁移，已经加载的线程不被静默中断或重建。
- Codex 的 provider 字段、HTTP/SSE 模式与当前构建差异属于 Adapter；Core 不了解这些语义。

### 普通插件：策略与产品

动态选 API、健康检查、重试条件、熔断、协议转换、流事件修复、UI、密钥管理策略等由插件选择实现。Core 与 Adapter 提供真实状态和控制点，不内建这些策略。普通插件也可以不依赖官方 Adapter，把 Core 通道接到自己的调用方。

## 实施顺序

1. 固定协议与权限：公开类型、错误码、超时/取消/流量边界、代次所有权；保留现有 Host ABI 与权限的行为。
2. 完成 Core 可运行实现及本机双上游 fixture：真实 POST 正文、路由改写、状态/头/正文变换、逐块响应、WS 双向文本/二进制变换、取消与清理。
3. 完成 Adapter 的 capability、兼容检查和客户端接入；用记录实际配置的原生连接 fixture 证明调用没有落到旁路连接或全局配置写入。
4. 写最小普通插件示例与使用说明，展示基础原语组合，不交付完整网关策略插件。
5. 集成回归、生命周期故障验证，并将确证覆盖与未验证边界写回本计划。Windows 执行实测；macOS 保持通用实现和类型检查，真实 Mac 验收另列，不虚报。

## 必须通过的验收

- 没有声明/授予权限时不能建立受管通道；旧代句柄在重载后失效。
- 两个本机上游服务证明请求确实到达插件选择的目的地址，方法、头和二进制正文可改写；原上游没有收到重复请求。
- 响应状态/头/正文改写能够被下游看到；多个 SSE 块在上游结束前到达下游。
- WS 双向改写/丢弃在真实 socket 验证；慢消费、超限、握手失败、子协议、关闭码、cancel 和 Host 退出均有确定结果；WSS 使用正常上游 TLS。
- 客户端取消、插件停用、撤权、Host 崩溃和通道关闭后，监听器及上游请求不会继续挂住；下一次启动不占用旧端口。
- 慢读、超限、抛错、决策超时及流中断有确定结果；不因失败新增隐式请求。
- 未授权 origin、重定向、逐跳头、错误认证、不支持的 upgrade/CONNECT 和并发超限的处理有明确测试。
- Adapter 使用同一 Desktop connection，在正确的 thread/start 或 thread/resume 阶段应用配置，并可注销；既有 preSubmit、读取/写入/事件功能回归通过。
- 使用说明准确区分 HTTP 通道、页面 CDP 与客户端内部 RPC；不能据 fixture 通过宣称所有官方登录模式及全部模型流量均已覆盖。

## 本轮实际交付与验证

- Core：`context.traffic.openChannel`，同一 generation-owned 端点支持 HTTP(S)/SSE 与 WS/WSS；`host.network` 和现有 origin 授权复用，每次请求及上游派发重新检查。短授权 RPC 与长流生命周期分开
- Adapter：`codex.backend.transport@1`、统一 channel descriptor、一次性 callback ticket、新建/恢复线程接入；旧构建独立报告不支持。客户端 provider/config 细节留在 Adapter
- HTTP：请求、响应、流改写；默认一次派发，可显式配置最多 8 次，必须消费或取消前一响应。Core 不自动重试
- WS：双向文本/二进制改写和丢弃；握手失败状态、子协议、立即到达的首帧、1005/1006 关闭、队列字节/帧数界限与有界回收均补有回归
- 清理：慢流及不返回的插件 iterator 可被取消，不继续占用通道并发槽；每代最多 4 通道，包含正在创建的端点。通过短 loader 和所拥有的临时 bootstrap 文件避开 Windows 命令行长度限制
- 文档：新增组合示例 `examples/http-channel`，缺少配置时不接入任务；运行时 Codlet skill 携带新接口说明与类型。skill 校验、示例 CLI preview、前端构建和 TypeScript 检查通过
