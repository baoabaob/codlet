# Native source adaptation

Native updates are reviewed from preserved package source before compatibility
tests. File hashes identify the evidence; capability contracts decide whether an
interface is usable. The [compatibility contract](spec/client-compatibility.md)
remains the runtime boundary.

## Implementation plan for the 2026-10-21 update

1. Capture the installed ASAR's app metadata and renderer/main-process JavaScript,
   recording the package identity, app version, build number, archive/header hashes
   and each file's size and SHA-256. Preserve the earlier reviewed renderer files
   as a partial baseline and report their missing modules explicitly.
2. Parse source with Acorn and resolve lexical bindings with ESLint Scope. Index
   declarations, assignments, imports, exports, calls and resolved references.
   Normalize names by their binding identity within each declaration. Shadowed
   variables stay distinct; free globals and property names retain their meaning.
   Read-only analysis never imports Native modules or executes their initializers.
3. Resolve semantic interface roles and map them to Core workspace capabilities:
   scopes, navigation signal/action, route and draft identity, transcript content,
   composer ownership, viewport state and shortcuts. Follow declaration-to-reference
   relationships, including query declaration → derived state → consumers.
   Discover roles across module boundaries and deduplicate re-exported identities.
4. Compare mapped roles and their dependencies. Separate exact/renamed/relocated
   structures, interface changes, behavioral changes and unresolved changes.
   Record both source locations, file hashes, matched constraints and consumers.
   Generate reviewable mapping/patch proposals only when their preconditions hold;
   uncertainty or competing candidates cannot become an automatic compatibility
   assertion.
5. Patch Core's discovery from those findings. The split plugin uses the public
   SDK and reflects required dependency readiness in its entry state. Preserve its
   layout, draft/attachment ownership, IME handling, conversation permissions and
   cleanup behavior.
6. Validate in layers: exact captured source, adversarial simulated structures,
   public SDK behavior, then an owned Native interaction session where feasible.
   Reports bind evidence to the Core/Native build and relevant source identities.
   A successful snapshot read, an exposed interface, a usable capability and an
   untested capability are separate outcomes. Unmeasured capabilities remain in
   the coverage inventory.

The daily Native process is not stopped or restarted for this work. Interaction
tests do not send messages to real conversations. Source snapshots remain local
generated artifacts; reports and small synthetic regression fixtures can be
committed independently of the Native distribution.

## Analysis dependencies

Acorn already supplies the repository's JavaScript parser. The pinned
`eslint-scope` dependency supplies resolved variables and references through its
[ScopeManager interface](https://eslint.org/docs/latest/extend/scope-manager-interface).
The analyzer preserves those relationships when comparing renamed code; equal
normalized syntax alone is not proof of semantic equivalence. The runtime uses
the same binding analysis on bounded function slices for shortcut data flow;
offline indexing can parse complete captured modules. Bundled dependency license
notices are generated by `frontend/build-codex.mjs`.

## Repeating the analysis

Use absolute paths and fresh output locations. Install the pinned frontend
dependencies first. Capture both packages while their files are still available:

```text
node scripts/native-source-snapshot.mjs --archive ABSOLUTE_APP_ASAR --package-full-name PACKAGE_FULL_NAME --output NEW_SNAPSHOT
node scripts/native-source-index.mjs --snapshot SNAPSHOT --output NEW_INDEX_JSON
node scripts/native-workspace-analysis.mjs INDEX_JSON NEW_ANALYSIS_JSON
node scripts/native-source-diff.mjs OLD_ANALYSIS_JSON NEW_ANALYSIS_JSON NEW_COMPARISON_DIRECTORY
node scripts/native-source-extract.mjs NEW_ANALYSIS_JSON all NEW_EXCERPT_DIRECTORY
node scripts/verify-native-workspace-source.mjs NEW_ANALYSIS_JSON NEW_VERIFICATION_JSON
```

For an already preserved, incomplete baseline, the snapshot command accepts
`--directory DIRECTORY --identity IDENTITY_JSON --evidence EVIDENCE_PATH`. It
records the missing archive and modules instead of claiming a complete package.
Indexing defaults to workspace entry modules and their static dependency closure.
`--root MODULE` selects other roots; `--all` indexes all captured JavaScript.
Neither indexing nor source extraction executes Native modules.

The diff accepts `--core ABSOLUTE_DISCOVERY_JS` to propose lookup edits after the
shared module-pool helper has been installed. The proposal retains predicates
and uniqueness checks and edits only calls bound to the imported resolver.
Review its preconditions, candidate hash and patch before applying it. Changed
data-flow predicates require a semantic patch. `--review REVIEW_JSON` applies
reviewed behavior/interface classifications only when both snapshot and
declaration identities match. The old `audit-native-working-current.mjs` entry
point delegates to this workflow; its former identifier-erasing comparison is
no longer an adaptation gate.

`prepare-native-readonly-probe.mjs SNAPSHOT SCOPED_STATUS_JSON NEW_DIRECTORY
ANALYSIS_JSON` builds a temporary diagnostic plugin for an already running
matching Native instance. It verifies loaded source hashes, checks the existing
connection and interfaces, and reads input ownership and main-surface structure.
It records focus, connection and root preservation separately. Its explicit
`host.raw`/`cdp.raw` scope is for this diagnostic only; retire it after copying
its report. A full lifecycle run remains a separate owned interaction test.

## Findings for build 20770

The current package is `OpenAI.Codex_26.1013.4894.0_x64__2p2nqsd0c76g0`,
app `26.1013.40934`, build `20770`. The baseline is package
`26.1007.9446.0`, app `26.1007.71326`, build `20398`.
The current workspace analysis indexes 281 modules and locates 28 roles.
Only two baseline renderer files were preserved; 21 roles can be located there.
Missing primary/transcript baseline modules remain unresolved.

| Source finding | Core/consumer change |
| --- | --- |
| Thread, Route and Composer scopes moved from shared to initial; navigation signal moved too | Discover responsibilities across loaded module namespaces and deduplicate re-exported identities |
| The keymap key occurs in both a query declaration and invalidation | Follow the query binding through the scoped getter, returned state and consumers; reject ambiguous data flow rather than repeated text |
| The viewport persistence writer can be exported by the same module | Resolve local exports as well as imported writers; distinguish the object namespace from callable lazy wrappers |
| Home composer values forward `homeDraftKey`; draft identity now prefers it | Keep Native's draft formatter and verify the controller's EditorProvider namespace |
| A composer root can contain both its main editor and a request-card editor | Qualify editors by controller and draft namespace before uniqueness; never choose by DOM order |
| Native retains inactive thread editors | Compare their RouteScope with the live navigation bridge before inspecting the main editor |
| Initial surface discovery can precede navigation ownership discovery | Rescan the surface once navigation preparation has installed its strict input reader |
| Split entry previously remained clickable after readiness failed | Gate the entry on required navigation/transcript preparation and strict input support; report optional shortcut failure separately |

The [reviewed change file](../codex/compatibility/native-source-reviews/26.1013.4894.json)
records both source positions and hashes for the home draft, Dot route and
internal editor-constructor changes. Core's local conversation contract is
unchanged; this review does not add Dot-route or composer-rebind support.
Unmapped external dependencies remain explicit in the diff.

## Coverage evidence

The functional consumer's generated inventory contains 219 public operations and
Native scenarios. `generate-compatibility-coverage.mjs OUTPUT_JSON` derives it
from the public type contracts and records their hashes. Evidence levels are
`source`, `simulated`, `interface`, `read` and `operation`. An absent observation
is `not-verified`. A readable management snapshot does not prove Native traffic
attachment; a prepared interface does not prove its interaction lifecycle.
Restored observations retain their original identities and are historical.

Local evidence for this update is retained under
`.codlet-artifacts/native-adaptation-20261021`: immutable source snapshots,
indices, analyses, original and reviewed comparisons, source checks, read-only
Native observations, test logs and delivery packages. Native source is not
redistributed in the repository. The release validation records the final
package hashes and the distinction between the resident Core and the candidate.

## Disposable Windows VM evidence

The 2026-10-21 lab is retained at
`D:/codlet-vm-lab/native-adaptation-20261021`. It contains an activated Windows
Enterprise Evaluation VM, the original signed build 20770 runtime, fixture
packages, guarded task scripts and per-attempt reports. The Store installed
`OpenAI.Codex_26.1016.6573.0_x64__2p2nqsd0c76g0`; the attempted interaction runs
explicitly selected the reviewed 26.1013 runtime in that registered package-family
context. These runs do not validate the newer Store build or an MSIX update.

All six selected executables passed OpenAI signature verification, and the ASAR
hash matches the source snapshot. The ordinary desktop user token was verified.
Four attempts stopped in preflight or the launch bridge before the interaction
probe began. In one measured run, signature checks took 24 and 36 seconds for the
two slowest files. No split-entry, multi-pane, draft, attachment or IME operation
is counted as passed from these attempts.

The host's Windows Hypervisor Platform feature was disabled. [QEMU documents that
feature as a prerequisite](https://www.qemu.org/docs/master/system/whpx.html) for
its supported WHPX configuration. Software emulation
and the available single-processor WHPX configuration showed excessive or unstable
latency. After the user approved the administrator prompt, the host component was
enabled with `-NoRestart` at 2026-10-21 06:19 UTC. Windows returned
`RestartNeeded: true`; the host was not restarted. The result is retained in
`reports/hypervisor-platform-enable.json` in the lab. Hardware-accelerated
interaction acceptance remains pending until the user restarts the host.

The cleanup boot subsequently entered Windows update servicing. Further
interaction runs must wait for servicing to finish and for the supported
hypervisor configuration to be available. VM start scripts now reject WHPX when
the host feature is disabled or its recorded installation still requires a restart.

The guest's full execution state was saved while servicing was in progress and
successfully restored in a paused VM. Its state stream, virtual disk and firmware
hashes remained unchanged after that check. Both the VM and local fixture server
have exited. After the host restart, `tools/resume-vm.ps1` in the lab validates
those files, restores the original TCG configuration and resumes the guest.
Finish guest servicing and the queued temporary-file cleanup before shutting it
down and starting with `tools/start-vm.ps1 -Accelerator whpx`. Cleanup preserves
session JSONL and database files. The local `reports/acceptance-status.json` and
`reports/vm-saved-state.json` retain the checkpoint and remaining steps.

The acceptance tools now record per-file signature results, permit explicit
bounded signature/startup budgets for slow disposable hosts, and emit startup
phase timing without private configuration. Production startup budgets are
unchanged. The local lab's limited-token launcher captures a real child exit code,
and its report writer serializes plain log strings instead of PowerShell's
filesystem metadata. An extended-budget run must record that setting and cannot
establish production startup performance.
