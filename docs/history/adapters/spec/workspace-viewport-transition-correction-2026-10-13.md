# Native viewport transitions and retained failures

Consumer sample `consumer-2782a256-2164-4517-a626-58ac3fe0c635`, using `09d016f`, enabled the Native pane and physically resized it from 480 to 520 CSS pixels. Its settled receipt `1791900953497-f26172b1-ae91-4877-90f7-5ae17922f05e` reported matching handle/config/Native widths, body width909, selected/native fixture1 and no errors. The following public select0 timed out; the later receipt showed fixture0/body8 without body/input errors but a generic `Native viewport retired` integration failure. This sample remains failed for C transition acceptance. Its earlier producer cause cannot be reconstructed from that message alone.

The consumer's actual transition first calls `bind(null)` while navigation is pending, then binds the confirmed thread. Null binding now clears/masks content without adopting an unconfirmed route or reapplying old thread flags to a newly mounted shell. It suspends stale listeners during that transition. The confirmed binding performs old-context restoration and new-context adoption.

Native motion/watch notifications receive a private current-route-and-strict-input guard from the workspace kernel. Old-context notifications cannot update workspace state or schedule a reapply against a new thread. Deferred configuration application additionally checks context nodes; temporary host/input readiness during a route transition is left to explicit confirmed binding. This is lifecycle coordination, independent of a grid or consumer cache policy.

Readiness, binding, update and notification failures retain the first error with a fixed phase prefix. If restoration also fails, both errors are retained and the primary code remains visible. Synchronous Native driver failures report through the same provider path as asynchronous failures. The workspace kernel retires the handle, withdraws the independent-viewport feature and publishes the original diagnostic; subsequent calls do not replace the cause with a generic retired message. Cleanup still completes through the existing awaited lifecycle.

Offline regressions cover pending null-to-confirmed binding with an already-queued old-context update, unchanged target state before confirmation, preserved width and original settings, primary-plus-cleanup failures, and automatic close while a bind is pending without a promise deadlock. They establish the candidate behavior only. A fresh consumer Native sample must verify the physical resize-to-navigation sequence, actual per-thread restoration and cleanup. The candidate is not an acceptance claim for the earlier failure.
