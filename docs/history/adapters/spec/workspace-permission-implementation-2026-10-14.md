# Generic Native permission operations and composer control lease

The Adapter provides current local conversation permission reads, independent authenticated writes, identity/revision events and a temporary composer-control mount point. The consumer owns its Core control/dialog, layout and selected/pending state. Core and the split repository were not edited for this change. The contract and types are in `workspace-permission-contract-2026-10-13.md` and `types/permissions.d.ts`.

## Native semantics and evidence

The current Legacy picker binds the committed Native input. Its normal setters also change host defaults and are deliberately not called. The producer learns already-loaded pure Native functions `$Ui` (options), `fM/kf` (conversion), `cM/tXe` (wire settings), `z_t` (canonical mode), `eWi/fWi/tWi` (built-in/default/Windows mode) and `qRi` (model confirmation classification). Unknown or ambiguous roles fail closed. It neither evaluates cached source nor forces an experiment flag.

Bounded discovery follows the current input's proven actual child/sibling path to the Legacy picker. It reads its current memo-cache inputs, actual menu visibility/disabled state and already-bound Native Windows requirement. Equivalent config/cwd/model-classification records are accepted; disagreement and pending state are explicit. Duplicate menu/profile records cannot overwrite a disabled item with an enabled item. Conversion uses the Native thread writable roots, otherwise its actual cached cwd query argument, matching `_Wi`; manager cwd is not guessed. Private configs, paths, managers, scopes and callbacks do not enter the public DTO.

## State and submission behavior

`Tta` carries the Native `agentMode`, `permissionProfileId` and `shouldSendPermissionOverrides`; `Ata` uses the override flag to construct Legacy wire permission fields. Reads of an unmodified thread therefore report these actual inputs, or the existing server-default baseline when overrides are off. They do not register the thread, adopt historical canonical policies, rewrite host defaults or raise access merely by reading.

After an explicit authenticated update, the plugin generation's registration guards that local thread's final `thread/resume`/`turn/start` dispatch. It waits for Native pending settings, reads latest canonical Native settings and changes only permission fields after other Adapter hooks. The registration survives temporary lease disposal and workbench exit, and is revoked by its owner or provider retirement. A resume inside the same pending update fails busy rather than waiting on itself. No additional backend, approval-response override, per-panel policy cache or rollback to an older cached permission exists.

Updates reserve the thread before their first await and validate the supplied revision again after Native conversion. A matching successful settings ACK plus requested Native read-back is required for confirmed. Older Native next-turn staging returns staged. Any failure after the operation may have run retains the live guard and reports outcome unknown. These paths have synthetic lifecycle/dispatch tests; they have not changed a real user's permissions.

The UI lease masks the small Native permission trigger and leaves the editor, draft and other controls in place. Pending bindings are inert. Native trigger replacement is reconciled through the existing workspace lifecycle; ambiguous candidates are masked until the failed lease is released. A passive failure publishes one bounded workspace diagnostic while keeping the rest of the surface available; it does not repeatedly throw from publishing or schedule an endless frame loop. Disposal restores still-owned fields from a journal, removes its events/container and clears that failure. The consumer unmounts its Core root separately.
