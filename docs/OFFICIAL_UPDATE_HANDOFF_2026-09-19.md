# Windows 官方更新交接与同时更新

## 实现

用户从 Codlet 启动客户端后，官方入口仍负责发现、下载和安装客户端更新。Core 为自己创建的主进程加载一个会话内原生桥，仅接管所选 `windows-updater.node` 的 `RegisterApplicationRestart` 导入。客户端文件、协议注册和其它进程不被修改。

模块使用文件身份核对，兼容 Windows 的路径别名；导入槽必须仍指向原生 API。守护启用时取消官方的独立重启登记，并通过保留在 Core 中的内核事件交接，即使客户端在登记后立即退出也不丢失信号。守护关闭或 Core 退出时恢复原生调用；DLL、状态和少量句柄保留到子进程退出，避免回调仍在执行时释放资源。

Core 只有在收到该安装信号、自己创建的客户端已经退出、同一官方包族存在更新版本且可执行文件可用后，才重新进入 Codlet 启动流程。保留注册表路径、watch/safe-mode 选项；普通退出不重启，已观察到的取消/失败会清除待重启意图。包注册等待上限五分钟。安装结果不确定时不启动第二个客户端，也不操作现有日常窗口。

官方状态读取限定在审计配置的主文档中。当前验证为应用 `26.915.31945` / build `9922`、Windows 包 `26.915.4065.0`。复用现有 AppScope 和 `L9.appUpdates`；通过导出的 `s7` 只读 selector 取得原有更新信号。不额外检查公开清单，不创建另一条应用服务连接。

## 同时更新

- 设置的 Codlet 更新按钮旁使用浅蓝色“同时更新”，仅在两项更新存在且可保留 Codlet 启动时展示；官方仍在下载则禁用并说明等待
- 原生确认框说明本地任务会中断；取消、Escape 和焦点返回均受支持
- 请求携带已确认的 Codlet candidate ID；Core 校验身份，重复点击合并为同一事务
- 先下载和校验 Codlet，准备经过校验的安装 helper，得到一次性就绪确认后才调用官方 `installUpdate()`
- helper 同时等待确切的旧进程退出和匹配当前事务的官方安装成功凭据，再替换 Codlet 文件并通过原启动器重启
- 缺失、取消或错误事务的凭据都禁止替换和重启；丢失接口响应不重复安装。已明确观察到官方取消/失败后，允许新的显式请求
- Codlet 更新源仍为未配置的开发状态，不伪造更新候选，也未打包或发布正式版本

## 验证

- 原生 Windows 测试使用独立子进程和测试 DLL 调用真实系统 API：只拦截启用的选定模块、其它模块不变、恢复原生调用、立即退出后事件仍可读取
- 88 项相关 Node 测试通过，覆盖控制器、GUI、原安装 helper 和隔离启动器；包含缺少/取消/错误/成功官方凭据的事务测试
- 17 项 Rust runtime-update 测试通过，另有原生桥两项和取消状态机测试；前端类型检查通过
- 实际官方模块已加载守护，dev 日志确认 `available:true`、`restartPreserved:true`、`error:null`
- 重启演练两轮通过；最终构建的管理进程 `32664` 保持，测试主进程 `36316` 退出后启动 `49552`，新 run `1789833285091-32664` 回到 `ready` 并确认插件运行时就绪
- 插件注册与偏好文件的 SHA-256 前后一致，官方包未变化，日常进程身份保持不变。证据位于 `.codlet-artifacts/official-update-restart/rehearsal-final-{before,after}.json`
- 使用实际前端构建检查了浅色、深色界面和确认/取消交互

上述演练不是一次真实官方包安装。隔离 dev 继续保持 `CODEX_SPARKLE_ENABLED=false`，以免升级与日常客户端共享的包。真实 MSIX/Store 跨版本安装仍需在有可用更新的专用环境中验收；macOS Sparkle 对应接管未实现，本次没有声称验证它。

## 本地演练入口

启动现有 `Start-TestClient.cmd`，待就绪后运行同目录下的 `Test-UpdateRestart.cmd`。它只向当前 dev 所属的 mailbox 写入固定演练命令，不下载或安装官方包。管理进程先回收旧子进程、插件运行时和后台服务，再接续启动一份新的 Codlet 测试客户端。新状态和报告仍在原 lab 日志目录中。

Windows 编译新增小型 C DLL 构建，使用匹配 Rust 目标的 MSVC 或 MinGW 编译器；最终 DLL 嵌入 Core，运行时不要求用户安装编译器。macOS 构建跳过这一 Windows 原生目标。
