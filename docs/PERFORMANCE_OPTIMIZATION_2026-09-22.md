# Core 与 GUI 第二轮内存优化 · 2026-09-22

本轮进一步降低了 Core 的常驻开销，并把 GUI 的控件、样式与主题监听改为随页面进入/离开创建和释放。**打开 GUI 时，Core 私有驻留内存从 6.41 MiB 降到 4.87 MiB，减少约 24%。重载后的累积仍未完全解决。**

对照版本为 `ebdbabd`，使用 [上一轮真实客户端数据](PERFORMANCE_MEMORY_2026-09-22.md)。本轮同样为 Windows 11 x64、Codex 26.915.4065.0、release 实验运行器、三个官方插件；Node 固定为 v24.21.0。不是安装包体积比较，也不是 macOS 内存验收。

## 实测结果

| 指标 | 上一轮 | 本轮 |
|---|---:|---:|
| 打开 GUI 时 Core 总工作集 | 26.33 MiB | 24.79 MiB |
| 打开 GUI 时 Core 私有工作集 | 6.41 MiB | 4.87 MiB |
| 打开 GUI 时 Core 私有提交量 | 8.36 MiB | 6.25 MiB |
| GUI 启用但未打开时 Core 私有工作集 | 6.25 MiB | 4.84 MiB |
| GUI 重载 60 次后的 Core 私有工作集中位数 | 6.96 MiB | 5.59 MiB |

工作集为实际驻留页面，私有工作集为其中的私有页面；提交量与 JS 堆是另外两种口径，不能相加或相互替代。原生数据丢弃各阶段前 15 秒，使用后续样本中位数；客户端、Core、官方后端、实验协调器/采样进程分开统计。

GUI 重载每次都确认 Core 的完成回执，每批结束对同样三个页面目标 GC，再测保留 JS 堆：

| 重载次数 | 上一轮堆总量 | 本轮堆总量 |
|---|---:|---:|
| 0 | 265.91 MiB | 265.43 MiB |
| 20 | 271.79 MiB | 281.67 MiB |
| 40 | 282.72 MiB | 284.15 MiB |
| 60 | 291.56 MiB | 288.65 MiB |

| 区间 | 上一轮增量 | 本轮增量 |
|---|---:|---:|
| 第 0–40 次 | +16.81 MiB | **+18.72 MiB** |
| 第 0–60 次 | +25.66 MiB | +23.22 MiB |
| 第 20–40 次 | +10.93 MiB | +2.48 MiB |
| 第 40–60 次 | +8.84 MiB | +4.50 MiB |
| 第 20–60 次合计 | +19.77 MiB | +6.98 MiB |

后续重复阶段的增长减小，但首次 40 次的总增量没有下降。不能把“第 20–60 次降低约 65%”说成总内存减少 65%，也不能声称本轮完全消除了热重载累积。两次独立运行存在原生客户端初始化、缓存和页面活动的差异；单次曲线不足以精确分摊每个对象的成本。

本轮第 20、40、60 次的 DOM 节点均为 1335，事件监听均为 1844，未随这几批重载继续增加。后台窗口截图和无障碍树曾滞后；随后同时核对了所持有进程、实际 DOM、布局与前台画面，GUI 正常存在，不是靠漏渲染降低占用。诊断阶段和一次未成功点击入口的阶段没有纳入上述常态对照。

## 实现变化

- **Core 共享不可变源码。** Renderer 的已验证源码快照与 Host 一样使用 `Arc<str>`，候选、当前状态、重载和补偿副本共享同一份内容。读取文件变化仍生成新快照；授权摘要序列化的内容保持一致。
- **退休代只保留轻量入口。** 不可变 ABI 的转发入口位于独立的小脚本；代次退休后清空指向整个运行时的引用。弱引用回归验证旧运行时对象本身可回收。隔离环境及代次身份保持独立，旧入口不能重新激活。
- **导航与重型 UI 分开。** 新增可选的 `context.ui.page()`：只注册侧栏入口时不初始化 SDK；原生页面真正挂载时才创建 UI 所有者，离开时同步卸载控件、释放样式和主题/语言/媒体监听。旧 `create().page()` 用法继续支持。
- **GUI 清理视图引用。** UI 组件、图标和页面组件引用随当前视图释放，长期操作回执状态仍由 Manager 管理。兼容没有新方法的旧 API 2 Core。
- **修复上一轮 CI 的模拟器契约。** Windows 顺序协议夹具现在分别验证两个注入脚本的注册、执行和移除，包括各自的会话与上下文；没有放宽为忽略额外请求。

实际客户端验证：离开 GUI 后三个目标中的 Codlet UI 容器和样式节点都为 **0**，保留一个轻量导航租约；再次进入恢复 **3 个容器、1 个样式节点**，插件列表可用。页面关闭后的整台客户端堆不必同步下降，因为原生新会话页也会初始化自己的对象；这里以受 Codlet 管理的资源生命周期作为直接证据。

## 验证与限制

- Rust 全目标、全特性测试：**620 通过，2 项原有忽略**；Clippy `-D warnings` 通过。
- Core JavaScript 全集：**130 通过**。
- GUI 原有 23 项功能回归通过；追加旧 API 2 回退用例，并复验新版页面关闭/重开，共 **24 个不同用例**通过。覆盖更新、安装、移除、设置、语言、标签、确认框及导航。
- 新增测试验证未打开/辅助窗口不创建 UI、离开后释放、等待注册期间退休立即撤除租约，以及真实 UI SDK 的 MessageChannel 清理与旧运行时回收。
- 本轮没有取得完整原生堆快照，不把尚存的全部增量归因于某一种对象。已有空隔离环境对照说明环境本身有保留成本；剩余问题仍需进一步定位。
- 本次只修改源码及测试运行器，未替换用户已安装的 Preview 4，未生成安装包或发布版本。实验结束后停止所持有的测试进程，恢复原实验配置；不改 Defender 设置或用户原客户端。
