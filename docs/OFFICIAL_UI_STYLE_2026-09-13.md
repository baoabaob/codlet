# 官方前端组件核对与 Codlet 界面规范

核对日期：2026-09-13。对象为本机 `OpenAI.Codex_26.908.4834.0_x64__2p2nqsd0c76g0`。本轮先完成代码研究、问题定位和组件设计，本文不是新版界面已经交付的声明。

## 1. 结论

上一版的问题来自组件边界不完整：有基础 DOM helper、主题变量和角色样式，但字号、颜色、图标、表单、反馈及页面交互又分别由 SDK、适配器和 GUI 临时处理。结果是父组件设置的视觉状态会被子元素覆盖，页面为了拼出形状再加行内样式，组件一组合就失去一致性。

官方前端的共同点是：使用语义主题变量；组件明确区分用途、尺寸、颜色和状态；页面主要负责组合组件及业务行为。React 是实现工具，单纯改用 React 或复制 class 并不会自动解决这些问题。

后续重构应先完成共享组件，再由 Codlet 管理界面、验收面板和官方插件共同使用。先修正继承和状态规则，再落实下面的页面调整。

## 3. 官方组件的风格与交互规则

### 字号与信息层级

当前 Electron 覆盖将 `--text-sm` 设为 13px、`--text-xs` 设为 12px；基础 `--text-base` 为 14px。样式表也有浏览器等场景的覆盖，应读取对应场景和主题继承，不能只搜索第一次出现的变量。字体设置、缩放和圆角设置仍会影响实际显示。

- 默认设置行的名称用 `text-sm`、中等字重、正常前景色。
- 说明用 `text-xs`、16px 行高、次要前景色，和名称之间相隔 2px。
- 行内操作使用小型按钮变体，常规字重；它的视觉强调不应超过名称。
- 版本等元数据使用说明级字号和颜色。说明本身应直接可读，不依赖悬停才能发现。
- 不给所有后代重新指定基础字号、颜色；组件子元素默认继承，需要表达另一种语义时才覆盖。

默认设置行左右 16px、上下 12px；紧凑行上下 8px。名称/说明区域可收缩，操作区不收缩。行高由内容和内边距决定，描述换行时允许长高。分组内部的细分隔线左右各缩进 16px。

### 按钮与返回

官方按钮将颜色、尺寸、圆角及内容布局分别作为变体处理。例如 `default`、`compact`、`icon`、`toolbar`、`dialogAction` 的几何和字号各不相同；`ghost`、`ghostSecondary`、`secondary`、`primary`、`danger` 则决定视觉强调。

状态规则也属于组件：正常、hover、active/open、focus-visible、disabled、loading。加载会禁用按钮并提供进度反馈，不能只换一句文案而仍允许重复提交。

截图中的“返回应用”实际使用共享导航项 `$R`。它包含箭头、文字、完整命中区域和默认启用的 `hover:bg-primary-ghost-hover`，并复用导航焦点规则。Codlet 的“返回”可以采用紧凑宽度，但必须保留同样的悬停与键盘反馈。不能用行内 `background: transparent` 压住状态样式。

### 搜索框与普通表单输入

官方页面搜索 `k5a` 是组合组件：容器、搜索图标、可访问标签、透明输入、清除按钮、可选尾部操作。

- 默认页面变体使用完整圆角，默认高度由 `--height-page-search` 决定；当前基础值为 32px。
- 图标、输入和尾部操作对齐；输入可收缩，图标和按钮不被挤压。
- 有内容时出现清除按钮；清空立即更新筛选。
- 快捷键搜索的消费者明确实现了 Escape 先清空非空查询，并阻止这次 Escape 继续关闭外层界面。
- 自动聚焦由调用方明确选择，不应在刷新、异步返回或切换语言时反复抢焦点。
- 普通路径/网址输入属于另一种表单组件。它有标签、校验、错误说明和可选尾部按钮，不应拿同一个裸 input 同时充当页面搜索。

### 选项卡、分段切换与开关

官方并不存在一种适用于所有地方的“大灰色底、等宽铺满”切换。

- `tabs` 有 `toolbar/page/pill/filter/browse/underline/segmented` 等变体，选中态和间距分别定义。
- `segmented-toggle` 默认 `inline-flex`；只有显式 `fullWidth` 才铺满，只有 `inset` 才使用包围式底板。
- 内容页切换有 `tablist/tab/tabpanel` 关联、`aria-selected`、单个 Tab 停靠点以及左右/Home/End 导航；代码还区分 RTL 和自动/手动激活。
- 设置开关则使用 `role=switch`、`aria-checked`，有独立 track/thumb。默认 32×20，另有 28×16 小尺寸；动画使用基本时长约 150ms，禁用时阻止交互。

Codlet 的本地/GitHub 两个导入来源是内容页选项卡，适合按内容宽度排列的轻量变体。开关的色彩应继续读取当前主题中的开关语义，不应因为截图是橙色就写死橙色，也不应擅自改成固定蓝色。

### 图标系统

客户端已有可复用的图标资产定义，包含名称、原始画布、viewBox、SVG body、可见边界和视觉中心。16px 与 20px 可能是不同绘制版本，不能统一拿 24px 路径缩放后就称为一致。

本轮确认的资产：

| 语义 | 当前官方资产 |
| --- | --- |
| 设置页“导入” | `arrow-down-open-base-light-16` / `arrow-down-open-base-light-20` |
| 刷新 | `arrows-clockwise-rotate-lg-light-16` / `arrows-clockwise-rotate-lg-light-20` |
| 返回 | `arrow-left-lg-light-16` / `arrow-left-lg-light-20` |

导入调用链已经核对：设置导航 `import` 配置引用 `nn/rn`，它们来自 `shared-icons` 的 `Us/Ut`，对应上述 16/20 资产。刷新资产本身是两段有留白的箭头，不是当前 Codlet 简化路径画出的近似闭环。

复用应集中在一个 `IconRegistry` 中，由适配层处理官方资产来源、画布和版本适配，调用方只使用 `import/refresh/back/info/folder` 等语义名。保留资产原有的 fill/stroke 和视觉边界，不再给所有 SVG 强制套相同描边参数。普通图标按钮提供简短 tooltip 和可访问标签；插件整行不提供说明 tooltip。

这些模块包含私有打包别名及 React 初始化依赖，不能直接把散落的哈希文件 import 当作稳定组件 API。本轮确认了可复用的资产与调用链；取得资产、统一提供给 SDK 的具体实现需要在组件重构时验证。

### 菜单入口

官方顶部菜单触发器默认是 tertiary 文字；hover/focus-visible 时使用浅背景及 description 前景；展开时才使用选中背景及正常前景。图标、文字子元素必须继承当前触发器状态。

Codlet 入口应是这一语义的专用 `MenuTrigger`。默认、悬停、键盘聚焦和打开状态都必须和相邻菜单同层级。保持现有经过核对的挂载位置，菜单视觉统一不意味着加入官方私有菜单集合或调用它的命令系统。

### 操作反馈

通知设置代码会更新对应设置的可见状态，失败时恢复旧值并发出错误提示；还使用 mutation ID 防止旧响应覆盖新操作。它没有把每次成功都作为一段持久文本插入列表前方。

Codlet 应区分四种信息：

| 信息 | 位置和时机 |
| --- | --- |
| 稳定内容：名称、版本、说明 | 列表行内持续显示 |
| 普通操作进度 | 对应按钮或行内反馈，保持布局稳定 |
| 普通启用/停用成功 | 开关反映已确认状态，无需顶部持久成功说明 |
| 错误、结果尚未确认、需要处理的冲突 | 与操作关联的错误/提示；可重试时明确提供重试，不伪装成功 |

通知设置的乐观更新不能直接套到插件生命周期：Codlet 的启用、重载、移除涉及真实运行时状态，仍应以已确认结果为准。视觉上的简化不改变现有确认、幂等及依赖检查。

## 4. 当前 Codlet 的具体问题

| 现象 | 当前代码原因 | 重构要求 |
| --- | --- | --- |
| 详情文字比名称突出 | 适配器对每个 `data-codlet-ui-owner` 元素设置 14px 基础字体；名称有 13px 角色规则，按钮内 caption span 又回到基础字号 | 基础字体只在组件根继承；按钮明确尺寸变体，caption 继承按钮 |
| 菜单 Codlet 文字变黑 | menu 按钮有正确颜色变体，但它的 owned 子元素被公共前景重置 | 子元素继承触发器状态，验证实际计算颜色 |
| 返回没有 hover | `bundled/runtime/ui.js` 的 `backButton` 写入行内透明背景、零内边距等 | 用 NavigationButton 的完整状态样式，禁止行内覆盖状态属性 |
| 刷新形状不对、导入图标笨重 | GUI 有 Lucide 定义，但实际 SDK `iconPaths` 是另一套简化路径，统一强制 24px viewBox/1.6 描边 | 一份图标注册表，复用已核对的官方资产及尺寸档位 |
| 搜索像普通表单框 | GUI 用普通 input 临时组装工具栏，没有 SearchField 的图标、清除及 Escape 语义 | 单独封装 SearchField |
| 本地/GitHub 过宽且厚重 | GUI 自己设置 tabs 底板、每个 button `flex:1` 和影子 | 使用轻量内容页 Tabs 变体 |
| 状态与成功消息挤占列表 | 行内运行状态 + 列表前的持久 `managementStatus` | 移除普通运行状态说明及普通成功横条；保留必要错误与未确认提示 |
| 兼容性说明被顶到最下面 | `clientStatusLine` 是列表后的普通段落 | 放到标题版本旁的可点击信息入口中 |
| hover 才能读到插件说明 | description 用于 tooltip，第二行用于版本 | 版本紧跟名称，说明直接显示在下一行，移除整行 tooltip |

这也解释了为什么上一轮“功能测试通过”不足以证明 UI 已统一：DOM 属性、按钮可点和接口成功并不能证明子元素的计算字号、主题颜色或 hover 状态正确。

## 5. Codlet 的页面调整决定

### 主列表

- 标题区保留 `Codlet`、版本和开发版标记，版本旁增加一个可点击的信息图标。标题区和搜索工具栏保持可见，插件列表拥有自己的滚动区域。
- 信息入口打开简短的版本/兼容信息浮层，容纳现有三种客户端提示及更新详情。通过点击、键盘聚焦后 Enter/Space 都能访问；不只依赖 hover。按 Escape 或点击外部关闭，焦点回到入口。
- 有 Codlet 更新时，沿用已经核对的“可下载/下载中/可安装/安装中”状态；提示图标与更新动作分工清晰，不把一段兼容性说明长期放在列表底部。
- 搜索采用带放大镜、清除按钮的圆角 SearchField；继续按 ID、名称、描述搜索。
- 导入与刷新均为简洁图标按钮，移除可见“导入”文字，保留 tooltip 与可访问名称。
- 每行第一行是“插件名称 + 较弱的版本号”，第二行是说明。名称和版本基线对齐，说明允许合理换行。没有说明时不补 ID/路径充数。
- 右侧保留低强调的紧凑详情操作、重载图标与开关；移除“运行中”等普通状态说明。
- 插件行不再显示说明 tooltip；普通启用/停用成功不增加顶部说明文字。

### 导入页

- 所有返回入口复用同一个 NavigationButton，包含 hover/focus/active 状态和足够命中范围。
- 本地文件夹/GitHub 使用按内容宽度排列的轻量 Tabs，不铺成两块等宽大按钮。
- 路径框与 GitHub 地址框复用 TextField 的标签、尾部操作和验证反馈规则。给用户显示的普通 Windows 路径不应暴露 `\\?\` 内部前缀；这只改变展示，真实路径验证仍由后端负责。
- 本地路径继续自动检查。用户输入期间不抢焦点，旧请求不能覆盖新值，切换语言保持输入。
- GitHub 查询是网络操作，保留明确查询动作；将“读取发布版本”的技术式文案改为面向用户的“查找版本”，作为字段尾部或邻近的紧凑操作。不会因为输入一个字符就反复请求远端。
- 验证结果显示识别出的插件信息；错误就近说明。底部主要操作有明确文本，并明确区分禁用、加载、可提交状态。
- 社区链接继续位于导入页，保留下划线及外链图标。

### 详情、确认页和验收面板

- 共用标题、返回、按钮和间距规则；验收面板也使用同一 NavigationButton。
- 详情仍显示 ID 和实际授予的权限，路径通过文件夹图标访问。
- 移除确认继续默认保留源文件；勾选删除、路径变化提示及后端校验保持现有行为。这里的确认内容是用户做删除决定所需的信息，不能为简洁而隐藏。
- 对返回、取消、关闭、提交分别定义行为，避免都调用一个模糊的“刷新页面”方法。确认弹窗关闭后返回原页面与原焦点。

## 6. 共享组件的边界

| 层 | 职责 | 不应承担 |
| --- | --- | --- |
| Codex 适配层 | 主题语义映射、官方图标来源与尺寸、宿主挂载位置、客户端版本适配 | 插件导入、移除等业务逻辑 |
| 共享 UI 组件 | 元素结构、样式变体、交互状态、键盘语义、焦点与生命周期清理 | 读取注册表、决定插件是否可以启用 |
| Codlet 页面 | 组合组件、绑定 i18n、请求业务数据、展示业务错误 | 临时重画图标、逐个指定字体颜色、覆盖按钮 hover |

组件目录至少包含：

| 组件 | 应封装的行为 |
| --- | --- |
| `Icon` / `IconButton` | 单一资产注册表、原始画布与尺寸、tooltip/可访问名称、忙碌状态 |
| `Button` | 明确用途/尺寸/颜色变体，caption 与 icon 继承，禁用及加载 |
| `MenuTrigger` | 默认/悬停/聚焦/展开状态，与当前菜单颜色语义一致 |
| `NavigationButton` | 箭头与文字、命中区域、hover/focus/active、返回事件 |
| `SearchField` | 搜索图标、清空、Escape 优先清查询、输入组合、焦点管理 |
| `TextField` | 标签、帮助/错误文本、尾部操作、busy/invalid 状态 |
| `Tabs` | 轻量内容页变体、关联面板、roving tabindex、方向键/Home/End |
| `Switch` | 确认后的值、pending/disabled/error、主题色和键盘语义 |
| `SettingsRow` / `SettingsGroup` | 名称/版本/说明/操作槽、长文本、分隔线和滚动适配 |
| `Popover` / `VersionInfo` | 锚定定位、视口避让、打开/关闭/焦点恢复；版本组件只填充内容 |
| `Feedback` | 行内进度、错误、必要的短消息；不产生持久成功横条 |

这些是拟定的组件边界，不代表当前 SDK 已经提供了全部接口，也不要求重新实现每个基础组件。优先评估官方公开组件库中已有的实现；Codlet 补充宿主主题、挂载和生命周期适配，以及自身需要的业务组合。

## 7. 重构顺序与验收

1. 先评估官方 Apps SDK UI 的组件、图标和样式隔离；同时去掉“所有 owned 子元素都重设字体/颜色”的规则，建立受控的根继承。
2. 复用可用组件，补齐导航、搜索、内容页 Tabs 等宿主适配；在独立组件页验证状态及组合，不直接在业务页堆补丁。
3. 用 SettingsRow 重做插件列表，再接入版本信息浮层、导入字段和就近反馈；同步替换验收面板的返回。
4. 在实际客户端核对默认、hover、键盘焦点、打开、禁用、加载和错误状态；同时覆盖深浅主题、中文/英文、窄窗口、长说明和多插件滚动。

关键验收应验证可观察行为与计算样式，而不只检查生成了某个 class：

- 详情文字不大于名称；按钮 caption 和 SVG 跟随父按钮变色；未打开时菜单 Codlet 与邻近菜单同层级。
- 鼠标移到返回/导入/刷新时有明确但克制的强调；键盘导航也能识别焦点。
- 非空搜索按 Escape 先清空，后续关闭行为独立；清空后结果恢复；输入法组合输入不触发意外导航。
- 插件数量增加时，标题、版本信息入口和搜索仍可见；列表不因一条成功消息上下跳动。
- 切换选项卡保持对应输入；异步结果不覆盖新输入或抢焦点。
- 行内没有普通运行状态，也没有插件说明 tooltip；说明直接展示，版本位于名称旁。
- 移除、授权、幂等和未知结果处理仍通过原有业务验证，组件改造不能把视觉成功当作运行时成功。

## 8. 官方公开资源与全面审查范围

补充核对：2026-09-13。用户要求将问题举一反三，截图和已指出的问题是审查入口，不能作为范围上限。

### 公开资源

- [Apps SDK UI 源码](https://github.com/openai/apps-sdk-ui)：OpenAI 官方 MIT 开源组件库，提供 React 组件、基于 Radix 的可访问交互、设计变量及图标。当前 README 要求 React 18/19 和 Tailwind 4；[组件文档与演示](https://openai.github.io/apps-sdk-ui/)由官方文档直接链接。
- [官方 UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)：包含颜色、字体、间距、图标、可访问性和不同展示形式的规则，并提供 Figma 组件库入口。原 Apps SDK 文档地址目前跳转到 Plugins 文档。
- [为 MCP 添加 UI 的官方指南](https://developers.openai.com/plugins/build/chatgpt-ui)：明确推荐可选的 `@openai/apps-sdk-ui`，并说明 UI 与工具数据处理的职责。
- [ChatKit 文档](https://developers.openai.com/api/docs/guides/chatkit)：主要服务于可嵌入的聊天体验、聊天内 widgets 和操作；不是 Codlet 插件管理窗口的通用组件基线。

Apps SDK UI 面向 ChatGPT 内的应用，并不是已核对的 Codex 桌面内部组件 API。当前查到的[官方开源清单](https://learn.chatgpt.com/docs/open-source)没有列出独立的桌面 UI 组件库。因此复用顺序调整为：先评估公开组件及图标，再对照当前桌面实现补齐宿主差异，不默认从零手写整套基础组件。

公开指南也有场景边界：例如不使用深层导航或内部滚动的要求针对 inline card，不能直接套到桌面管理对话框。Codlet 的滚动、焦点及导航应以桌面场景为准；字体、颜色、信息层级和可访问性原则可以共用。
