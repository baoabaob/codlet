# Core 后台 Native 测量

2026-10-11（Asia/Shanghai）。用户选择先完成后台测量。本轮已完成；测试实例已正常关闭，登录与报告保留。日常客户端未被操作。

## 范围和结果

在独立 Native 客户端的逻辑 Chromium 文档中运行 Core React/SDK 受控组件，覆盖 0/1/2/4/5/8 roots × 20/200/2000 个固定项 × scheduled/sync × neutral-split/styled，共 **72 场景**。这不是 Native 正文或输入器组件的成本。

- 正式 7,200 次 render 请求得到 7,200 次 commit，无取消、无缺失，DOM 修订号匹配。每场先完成初次 commit 和 5 次预热，再采样 30 批；每批等待所有 root 的真实 commit。
- 同签名主题通知共 2,160 次：旧容器属性写入 0。新增单个容器时，对已有容器的写入均为 0；模拟主题切换后的回执匹配，并还原 class/data-theme。
- 额外突发测试：200 请求得到 8 次 commit、192 次合并；8 个待提交更新在卸载时取消，迟到 commit 为 0。
- 12 组独立 idle 样本覆盖 6 种 root 数 × 两种样式。每 root 固定 2,000 项；等待 60 秒，含端点采集的实际窗口为 61.07–61.16 秒。静态树稳定后，调度方式合并为 scheduled，不宣称测了另一套 sync idle 矩阵。
- 每场结束自有容器、DOM、UI observer/media listener 均为 0。插件生命周期的语言 observer 单独区分，由 Core 在退役时清理。6 项夹具回归通过。

机器为 Windows x64，20 个逻辑处理器；Native 包 `26.1007.2314.0`，实际引擎 `Chrome/155.0.8059.40` / V8 `15.5.35.20`。使用 release lab，SHA256 `748db69aebd09ba61de97b1487aeb6c9a52dc0b398e51fdc2bf04657f9c563c3`；UI bundle SHA256 `e7644939e6d08415fac865a3019b676485b75375d41d69f9efcc11968731d78d`。

完整统计：[JSON](core-ui-native-background-2026-10-11.json)。原始样本、历史计时校正记录、退出回执和测量时源码保存在 `.codlet-artifacts/core-native/core-e674f238-bc43-483c-bdb1-8b90802cbe3e/`。正式 active 与 idle 的夹具 hash 分开记录：idle 完成后仅调整了活动计时边界/诊断方法，静态 fixture 和 Core 二进制没有变化。

## 调用、commit 与夹具构造

每 root 使用重复的 pre/button/aside/p；每次更新重建固定 React 元素树，轮换两处文本。**元素树先在计时外构造**，其时间另列；request 只测 Core render 调用。首轮包含构造时间的报告已单独保留，不用于下表。

8 roots × 2,000 项压力条件，单位 ms，P95；调用/commit 各 n=240，整批及构造各 n=30：

| 样式 | 模式 | 调用 | 单 root commit 等待 | 整批到任务边界 | 整批夹具构造 |
| --- | --- | ---: | ---: | ---: | ---: |
| 中性正文＋样式控件 | sync | 6.0 | 6.0 | 45.0 | 67.3 |
| 中性正文＋样式控件 | scheduled | 0.1 | 38.4 | 46.9 | 70.6 |
| 正文及控件均有 SDK 样式 | sync | 5.5 | 5.5 | 41.8 | 73.1 |
| 正文及控件均有 SDK 样式 | scheduled | 0.1 | 45.4 | 55.4 | 63.0 |

scheduled 明显缩短本次调用占用，但工作仍需执行，排队体现在 commit 等待中。单 root commit 和整批完成不是同一指标。这里不能推出 Native 输入更快，也不支持把所有同步路径无条件改成异步；保持旧 mount 兼容、让调用者选择 mountReact 的方案成立。

夹具构造本身的批次成本也很高。因此消费者需要保留不变子树、减少无关内容重建，调度只解决让出调用栈的一部分问题。该判断针对这份合成树，不是对 Native 编辑器的性能归因。

## 主题与作用域

中性 root 不处于 `[data-codlet-official-ui]` 祖先中，控件以 portal 放入单独样式容器；两种样式条件使用相同数量和结构的内容项。语义边界及零冗余写入在全部场景通过。

大树上创建新容器约 254–273 ms；模拟主题切换到下一任务边界的 P95 为中性正文约 400–408 ms、全样式正文约 836–843 ms。**这些数值含逻辑文档中的样式重算及 Native 自身响应**，且后台可能积累尚未结算的样式工作，不能称为 Core 纯循环开销或真实呈现延迟。它们提示缩小样式作用域有价值，但不足以证明真实 Native 正文的视觉和前台性能。

## 回收和窗口边界

自有 UI 对象移除与浏览器 GC 分开验证。完整压力序列后短期仍可观察到分离 DOM，未据此声称全局节点立即清零。独立 8×2,000 周期从基线 3,451 节点到挂载 35,518，卸载及两次 GC 后为 3,466；额外空 flushSync 没有进一步下降。不支持为此增加 Core 强制 flush。idle 序列全局 DOM 基线 2,453、结束 2,460；Native 后台本身也会改变全局计数。

最后移除临时注册，回执 applied、无 target failure；正常 quit 后 Host 退出码 0。退出回执及当时的独立复核均记录 **27 个 PID＋创建时间身份无存活项**，包括测量 Host。该结果证明记录身份已退役；旧退出记录也缺少父子身份链，不能额外认证所有非根进程的归属。日常 Desktop 47704、CLI 41872/55628 创建身份保持一致；同时存在的其他 Adapter 测试进程已退出，因此不声称所有外部测试进程都未变化。没有清除登录资料或复制日常凭据。

不能仅由 `visibilityState:hidden` 判断用户没有展示原生窗口。Adapter 的既有记录证明旧版 Native UIKit 可以前台显示而 backing document 仍 hidden；该旧证据不直接替代当前版验证。本轮当前版 CDP 的 `Browser.getWindowForTarget` 返回 `Browser window not found`，OS 同时存在所属原生窗口，说明不能直接沿用普通浏览器窗口映射。用户选择后台测量后，本轮特意最小化所属原生 HWND，Win32 复核 `IsIconic=true`；这些样本的实际后台条件成立。

当前版 Native UIKit 的 HWND→逻辑 Target→真实呈现帧尚无完整映射/计数证据。今后的前台验收应寻找有依据的 Native 呈现指标，**不再仅等待用户把 backing document 变成 visible**，也不伪造文档可见性。当前报告没有可见帧、前台长任务或 Native 控件输入响应结论。
